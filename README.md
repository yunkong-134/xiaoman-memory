# xiaoman-memory

给 DSH 的长期记忆：纯文本、不向量、不联网。

它只做一件事——记住发生过的事，下次提起来。

## 它是什么

不把聊天记录塞回上下文，而是把事写成条目存下来，回想时按关键词和日期去找。库是你自己的 Markdown，随时能打开看、能改、能拷走。

一条事长这样：

```
### E012 2026-11-02 备份脚本跑到一半就断
〔事〕23:50 那次备份只拷了工作区顶层，剩下的没跑完。
〔判〕2026-11-02 定时任务被宿主收走了，脚本本身没坏。
〔源〕本场对话。
〔元〕备份、脚本、计划任务
〔情〕-1
```

`〔元〕` 是这条事挂的词，回想靠它们找回来。`〔情〕` 只有两档：有情绪写 1 或 -1，没有就不写。

## 装

```
dsh plugin --profile web add https://github.com/yunkong-134/xiaoman-memory/releases/download/v3.0.0/xiaoman-memory-3.0.0.tar.gz
```

装完是空的，这是故意的：它记的是你的事，不是模板。

## 第一条

装完会有一个 `第一条.md`（在记忆目录里），里面写着怎么起第一条。三步：

一，打开 `~/.dsh/memory/记忆库/事件库.md`。
二，照顶上的格式写一条真事。标题要带日期，正文四格：`〔事〕〔判〕〔源〕〔元〕`。
三，跟她说一句「我今天……」，看下次她能不能翻出来。

不想手写也行，跟她说「记一下：今天……」，她照格式起一条，你再看一眼改。

## 两个工具

`memory_check`：查格式，外加列「待收的词」。少了 `〔元〕` 的、元素表行坏的、理解库标题没日期的，一次列出来。格式坏的地方不会报错——回想只是悄悄看不见那条，所以得有个东西替你喊。

`memory_explain`：查「为什么没想起来」。给它一句话，它说清这句话点到了哪些元素、实际交出来哪几条；再给它一个编号，它说清那条是没被点到、沉底了、还是分数不够。

## 全忆：原话放另一处

事件库里是摘要，原话在 `全忆/日期.md`，一行一条：`14:32:10 他  原话`。

装完会铺一份 `全忆/说明.md`，里面写了三种记法。插件不替你写——它读不到会话存档，也不该替你判断哪句算原话。你贴、让 agent 写、或者自己写个导出脚本，都行。

摘要条目的 `〔源〕` 指回原话，比如 `全忆/2026-11-02.md 14:32:10`。看摘要觉得不对劲，顺着这一行能走回原话。

## 元素怎么长

不用专门的脚本，靠 `memory_check`：

它会列出「事件里出现、元素表里没有的词」，按出现次数排。比如跑一次看到 `吃、面、备份`。你挑该收的，写进 `元素表.md` 一行：

```
    〔元〕备份｜抽象｜别名：存档、拷贝｜条数 3｜
```

收录的标准只有一条：这个词换一件事还认得出来吗。认得出来就收，收完它会自己挂到条目上。

## 库存在哪

默认 `~/.dsh/memory/`，改 `DSH_MEMORY_DIR` 可以换地方。里面全是纯文本：

- `记忆库/事件库.md`：事
- `元素表.md`：词和它挂在哪些事上
- `元素-多义表.md`：一个词面指好几个意思时怎么分
- `理解库.md`：词本身是什么意思（可选，不建也能用）
- `记忆库/权重.json`：每件事的重量，越久越轻

## 想不起来的时候

先跑 `memory_explain`，别靠猜。

三种常见结果：没点到元素（换个说法，或给那条事补个 `〔元〕`）；沉底了（太久没被想起，权重掉到线下）；分不够（点到了，但输给别的条目）。

## 回想是怎么判断的

一句话进来，先认它从哪儿进来——轴：

- 说「十一月那次」「前天」「上周」，定时间轴，按标题里的日子对；
- 问「为什么」「凭什么」，定事由轴；
- 有怕、烦、紧、难受这类词，定情绪轴；
- 有人称，定人轴；
- 都没有，就是词轴。

轴定了以后，那条轴上的证据先说话，别的只负责排次序。日期对上的那条压过标题里撞上来的碎片。

每个词块还能写一行 `又叫：鲸鱼、鱼类`，那是别的说法，只给匹配用，不念出来。

`理解库.md` 记的是词本身的意思（可选）：元素管「这个词挂着哪些事」，理解库管「这个词是什么」。

## 3.0 改了这些

- 回想重写：认轴（时间／人／情绪／事由）、认相对日期（前天、昨天、上周）、按日子优先排、单字也能进检索。
- 出生权重按标题日期算，没称过的事也会随时间变轻；沉底的还能被联想捞上来。
- 理解库：词本身什么意思，跟「这个词挂着哪些事」分开；块里能写 `又叫：` 收别的说法。
- 装完有 `第一条.md`，三步能跑起来。
- `memory_check`：格式错会报，不再静默。
- `memory_explain`：想不起能查到底为什么。
- 元素表自带六个示范行（文件、备份、计划、情绪、时间、人物），装完不是空的。
- `memory_check` 也扫全忆：时间戳格式不对的行、文件名不是日期的，都会报。
- 装完会铺 `全忆/说明.md`。
- 注入里标题后面挂半句〔事〕，不再只报菜名；每个会话第一次注入会说清两个工具和「记一下：……」的说法。
- 写库上锁：补元素时先拿 `事件库.md.lock`，拿不到就跳过；锁超过两分钟算陈锁，会被接管。
- `〔情〕` 说清只有两档。以前让写 -3..3，但权重把绝对值截到 1，写 3 和写 1 一样重。

## 还没有的

- 没有向量：同义词只能靠理解库里手写「又叫」。
- 全忆只给了格式和说明，没有导出脚本——那个跟 DSH 版本的存档格式绑着。
- 权重和半衰期的数字是拍的，没做过实验。
- 多进程同时写同一份库：有锁，但只保护补元素那一步。
