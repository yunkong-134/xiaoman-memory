# 全忆要干什么

这里存原话，事件库存摘要。两个东西分工不同，别混：

- `记忆库/事件库.md`：一条事一块，写发生了什么、我当时的判断。回想只翻这里。
- `全忆/日期.md`：按天一个文件，一行一条，前面是时间和谁说的。要还原当时的原话，来这里。

## 怎么写

一个文件一天，文件名 `2026-11-02.md`：

```
# 2026-11-02

14:32:10 他  这个插件装了没反应，你先别动配置
14:33:02 我  我先看 diag，没动配置
```

行的格式就三样：`时:分:秒  他/我  原话`。原话不改，不删，不总结。同一秒有多条就全留着。

## 谁来写

插件不替你写——它读不到会话存档，也不该替你判断哪句算原话。

三种写法，挑一种：

一是你自己贴：每次聊完，把要紧的几句粘进来。
二是让 agent 写：跟它说「把刚才那几句原文记进全忆」，它有文件工具，会照格式追加。
三是写个导出脚本，从会话存档里读——这一步跟具体 DSH 版本的存档格式绑着，换版本可能就废，所以没放进这个插件。

## 事件里的〔源〕怎么指

摘要条目的〔源〕写清原话在哪，比如：

```
〔源〕全忆/2026-11-02.md 14:32:10
```

这样以后看摘要觉得不对劲，能顺着这一行走回原话。

## 别做的事

不要把摘要写进全忆，也不要把原话抄进事件库。一份摘要、一份原话，各有各的用处；合成一份，两样都不好用。
